# Участие в разработке

Для локального запуска используйте [README](README.md). В [техническом описании](TECHNICAL_SPEC.md) зафиксировано текущее поведение, в [дорожной карте](ROADMAP.md) — дальнейшие направления.

## Изменения

В issue или pull request опишите проблему, ожидаемое поведение и способ проверки. Для визуальных изменений полезны снимок или короткая запись локального воспроизведения без персональных данных.

Перед отправкой выполните относящиеся к изменению проверки и проверку публичного содержимого:

~~~powershell
npm --prefix client test
npm --prefix client run build
dotnet test server/CatsFootball.sln -c Release
node tools/check-publication.mjs
~~~

Изменения сетевого формата сопровождаются обновлением описания протокола и общих тестовых данных. Проверки должны подтверждать поведение, а не только повторять реализацию.

## Публичные материалы

Используйте вымышленные адреса и тестовые данные. Не включайте рабочие конфигурации, ключи, пароли, токены, журналы, дампы, локальные пути пользователя и внутренние инструкции эксплуатации.

Настройки локальной среды и приватные материалы храните вне отслеживаемых файлов. Перед добавлением новых файлов проверяйте git status и содержимое diff.

Уязвимости не следует публиковать в обычных issues: используйте [приватное сообщение](SECURITY.md).
